# 部署指南

从零到在 QQ 里跟本机 DSH 说上话。

## 0. 你需要什么

- 一台**有公网地址**的服务器跑 AstrBot（版本 `>= 4.18`，插件 Web API 需要它）
- 一台**装着 DeepSeek Harness** 的机器（可以就是你的笔记本，在家里 NAT 后面也没关系）
- 一个 AstrBot 已经接好的聊天平台（QQ / 微信 / Telegram / 飞书 / Discord 都行）

方向是 DSH 主动连出去，所以**只有 AstrBot 需要公网地址**。

---

## 1. AstrBot 侧

### 1.1 放插件

把 `astrbot_plugin_dsh_bridge/` 整个目录拷到 AstrBot 的插件目录：

```bash
# 在 AstrBot 部署目录下
cp -r astrbot_plugin_dsh_bridge data/plugins/
```

然后在 WebUI 的插件管理里重载插件（或重启 AstrBot）。

插件没有第三方依赖，不用 `pip install`。

### 1.2 生成共享密钥

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

把这串记下来，下一步和 DSH 侧都要用同一个值。

### 1.3 配置插件

WebUI → 插件管理 → DSH Bridge → 配置：

| 字段 | 填什么 |
| --- | --- |
| `hmac_secret` | 上一步生成的随机串 |
| `forward_mode` | 先用 `direct`（私聊 + 群里 @机器人） |
| 其余 | 保持默认 |

保存后插件会重载。

### 1.4 建一个 API Key

WebUI → 设置 → API Key → 新建：

- 权限**必须勾选 `plugin`**（插件路由的挂载点强制要求这个 scope）
- 复制出来的 `abk_...` 字符串

> 这是 AstrBot 自己的钥匙，和上一步的 `hmac_secret` 是两把不同的东西，都需要。

### 1.5 先自己验一下

```bash
BASE=https://your-astrbot.example.com/api/v1/plugins/extensions/astrbot_plugin_dsh_bridge
KEY=abk_你的key
SECRET=你的hmac_secret

EXP=$(( $(date +%s) + 300 ))
SIG=$(python -c "import hmac,hashlib,sys;print(hmac.new(sys.argv[1].encode(),sys.argv[2].encode(),hashlib.sha256).hexdigest())" "$SECRET" "$EXP")

curl -s "$BASE/health" -H "Authorization: Bearer $KEY" | head -c 400
echo
curl -s "$BASE/whoami" -H "Authorization: Bearer $KEY" -H "X-DSH-Bridge-Token: $EXP.$SIG"
```

`/health` 不需要令牌也能看到队列水位；`/whoami` 会回显钥匙是否被识别。
如果这里 401，先解决鉴权，别急着装 DSH 侧。

## 2. DSH 侧

### 2.1 装插件

用 DSH 的插件安装流程把 `dsh-plugin/` 装进你的 profile（本地目录也可以）。

> **装完要重启 profile 才会加载。** 本插件带着 `dsh.bundle.patch`，属于 **bundle 插件**：
> 安装器只会把它加进 `dsh.profile.bundles` 层栈，并明确提示
> 「restart the profile to load it」——它**不会**热加载（只有不带 bundle 的普通插件才会被就地挂上）。
> 这一点很容易踩：装完没重启，看起来一切正常，实际插件根本没跑。

重启后可以在 WebUI 的 **插件 → 插件清单** 里看到 `dsh-astrbot` 这一行（只读）。
这里只提供主机端、没有客户端界面，所以它**不会**出现在「插件配置」页里。

### 2.2 填配置

在 profile 的 cordis 配置里，给插件加上配置块（`cordis.patch.yml` 里已经给了模板）：

```yaml
- insert:
    - id: dsh-astrbot
      name: 'dsh-astrbot'
      config:
        baseUrl: 'https://your-astrbot.example.com'
        apiKey: 'abk_你的key'
        secret: '你的hmac_secret'
        workspace: '/path/to/your/workspace'
        commandPrefix: '/'
        sourceHint: true
```

`cordis.patch.yml` 属于 profile 层，默认的 web profile 是 `patchReload: live`，
所以**配置改动会热加载**（注意：这跟前面「装插件要重启」不是一回事——装插件动的是层栈，
改配置动的只是行配置）。日志里应该出现：

```text
[dsh-astrbot] 已连上 AstrBot 桥接插件 v1.0.0，待取事件 0 条
[dsh-astrbot] 已启动，长轮询 https://.../api/v1/plugins/extensions/astrbot_plugin_dsh_bridge
```

连不上也不会让 DSH 起不来：插件会记一条错误，然后在后台按指数退避持续重试。

## 3. 用起来

在 QQ 里给机器人发一条私聊：

```text
你：帮我看看当前目录有哪些文件
```

DSH 那边会开一个 Harness 会话，跑完之后把结果发回这个会话。
再发一条消息会**接着同一个会话**继续（模型记得上下文）。

| 命令 | 作用 |
| --- | --- |
| `/new` | 开新会话 |
| `/stop` | 中断当前任务 |
| `/status` | 看桥接状态和当前绑定 |
| `/help` | 帮助 |

群里默认要 **@机器人** 才会转发，避免把群里闲聊全部灌给模型。

## 4. 排查

| 现象 | 先看哪里 |
| --- | --- |
| DSH 日志说 401 | `apiKey` 有没有填、scope 有没有勾 `plugin`、`secret` 和 AstrBot 侧是否一致 |
| 日志说连不上 | `baseUrl` 是否可达；DSH 所在机器能不能访问公网 |
| 消息发出去了但没人回 | AstrBot 侧 `/dsh状态` 看队列水位：如果 `待取事件` 一直在涨，说明 DSH 没在取件 |
| AstrBot 自己也回了一遍 | AstrBot 侧 `suppress_default_llm` 保持 `true` |
| 群里不响应 | 要么 @机器人，要么把 `forward_mode` 设成 `all` |
| 回复被截断 | AstrBot 侧 `max_message_chars` 和 DSH 侧 `maxReplyChars` 一起调大 |
| 明明发出去了但 DSH 重复处理 | 正常不会；`recentIds` 只保留 200 个，极端情况下重启后可能重放。可调大 `state.json` 里的上限（见源码） |

打开 AstrBot 侧 `debug: true` 和看 DSH 日志能覆盖绝大多数问题。

---

## 5. 加固

- **上 HTTPS**。协议裸奔意味着 API Key、HMAC 令牌和聊天内容都是明文。
  用 Nginx / Caddy 反代并强制 TLS。
- **限制来源**。如果 DSH 出口 IP 固定，在防火墙上只放行它访问 AstrBot。
- **收紧准入**。DSH 侧 `allowUsers` 只放开你自己的账号 id。
- **别把 `hmac_secret` 和 `apiKey` 提交进 git**。
