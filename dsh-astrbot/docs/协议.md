# 两端之间的协议

AstrBot 侧插件 `astrbot_plugin_dsh_bridge` 与 DSH 侧插件 `dsh-astrbot` 之间只有这一份约定。
两端各有一份实现（Python / JavaScript），协议变更必须同时改两边，并且把测试向量一起更新。

## 挂载点

```
<baseUrl>/api/v1/plugins/extensions/astrbot_plugin_dsh_bridge/<端点>
```

前缀由 AstrBot 决定，不是本项目选的：所有插件 Web API 都挂在
`/api/v1/plugins/extensions/<plugin_name>/` 之下。
DSH 侧配置可以只写站点根地址，`resolveBaseUrl()` 会自动补全；已经写全了则不重复补。

## 鉴权：两把钥匙

**第一把 —— AstrBot 的 API Key。** 挂载点强制要求 plugin scope，绕不过去：

```http
Authorization: Bearer abk_xxxxxxxx
```

**第二把 —— 插件自己的共享密钥。** 用 HMAC-SHA256 签一个过期时间：

```http
X-DSH-Bridge-Token: <exp>.<hex(hmac_sha256(secret, str(exp)))>
```

- `exp` 是 Unix 秒级时间戳，客户端默认取 now + 240s（留 30s 余量提前换新）。
- 服务端要求 `exp >= now`，否则拒绝。
- 比较用常量时间函数（Python `hmac.compare_digest`）。
- 未配置 `hmac_secret` 时**一律拒绝**，不会退化成「无密钥也能用」。

跨语言一致性由测试守住：两端都把向量
`key="test-secret"`、`msg="1700000000"` 的结果硬编码为
`1b74eaf87da46877ba651ac812b24a3bf01990e9ed0101b88268f60f965729e2`，
任何一端改动算法都会立刻失败。

鉴权失败返回 `401` 与 `{"message": "unauthorized"}`（`error_response` 的形状）。

## GET /health

探活。**刻意不做鉴权**（方便用浏览器 / 监控探活），只暴露非敏感计数。

```json
{
  "ok": true,
  "plugin": "astrbot_plugin_dsh_bridge",
  "version": "1.0.0",
  "server_time": 1789200000,
  "data_dir": "...",
  "enabled": true,
  "forward_mode": "direct",
  "features": { "inbox": true, "reply": true, "images": true, "stop_event": false },
  "cursor": 12,
  "delivered": 12,
  "queued": 0,
  "received": 12,
  "sent": 12,
  "send_failed": 0,
  "dropped": 0,
  "uptime_sec": 3600
}
```

## GET /inbox

长轮询取件。这是整个协议的核心。

| 查询参数 | 默认 | 说明 |
| --- | --- | --- |
| `cursor` | 0 | 上次拿到的序号；只返回严格大于它的 |
| `timeout` | 25 | 没有事件时最多挂起多少秒（支持小数）；被服务端 `max_poll_seconds` 夹住 |
| `limit` | 20 | 单次最多返回几条（上限 100） |

响应：

```json
{
  "ok": true,
  "cursor": 12,
  "head": 12,
  "events": [ /* 见下面的事件形状 */ ],
  "more": false
}
```

语义细节（两端都按这个实现，测试也按这个断言）：

- `cursor` 是**单调递增的整数**，由 AstrBot 侧在入队时分配。
- 返回的 `cursor` 是「本次取走的最后一条的序号」；没有事件时原样回传请求里的值。
- 取走即裁剪：AstrBot 侧会把 `cursor <= delivered` 的事件从队列里删掉。
- `more=true` 表示可能还有（本次正好取满 `limit`），客户端应立即再取一次。
- **DSH 侧先处理事件、再落盘游标**：中途崩溃最多重放，不会丢消息。
- 队列超过 `max_queue` 时丢最旧的未取事件，并累加 `dropped`。

### 事件形状

```json
{
  "kind": "message",
  "cursor": 7,
  "id": "evt-1789200000-7",
  "umo": "aiocqhttp:FriendMessage:10001",
  "platform": "aiocqhttp",
  "platform_name": "aiocqhttp",
  "text": "帮我看下今天天气",
  "sender_id": "10001",
  "sender_name": "小明",
  "group_id": "",
  "is_private": true,
  "mentioned": false,
  "images": [ { "mediaType": "image/jpeg", "base64": "/9j/4AAQ..." } ],
  "notes": [],
  "ts": 1789200000,
  "time": "2026-09-12 14:30:00"
}
```

- `umo` 是 AstrBot 的 Unified Message Origin，格式 `<platform_id>:<MessageType>:<session_id>`。
  它是**不透明的路由键**：DSH 只负责存下来并原样回传，不去解析它的内部结构。
- `id` 用于 DSH 侧去重（游标重放时不会重复跑同一轮任务）。
- `images` 内联 base64（而不是给 URL），是为了避免让 DSH 反向访问 AstrBot 的文件接口——
  那需要额外一轮鉴权和生命周期管理。代价是单次响应更大，所以有 `max_image_bytes` / `max_images` 限制。
- `notes` 是「有东西没带上」的人类可读说明（图片超限、读取失败等），
  DSH 会把它作为一条提示附在提问前面，而不是静默丢弃。

## POST /reply

把结果发回原会话。

```json
{ "umo": "aiocqhttp:FriendMessage:10001", "text": "今天晴，25 度。" }
```

成功：

```json
{ "ok": true, "sent": 1, "chunks": 1 }
```

当 `text` 超过 `max_message_chars` 时，AstrBot 侧会按段落 / 句子边界切分成多条依次发送，
`chunks` 是切出来的条数，`sent` 是实际发出去的条数。

失败（`umo` 不合法、平台不在线——`context.send_message()` 找不到平台时返回 False）：

```json
{ "ok": false, "sent": 0, "chunks": 1, "error": "send_message 失败：平台不在线或 umo 不合法" }
```

注意这里 `ok=false` 用的是 **HTTP 200**：请求本身被正确处理了，只是投递没成功。
DSH 侧据此记 `send_failed` 并在日志里说明，但不会重试刷屏。

参数校验失败（缺 `umo` / 空 `text` / `text` 不是字符串）返回 `400`。

## POST /reset

清空待取队列（调试用）。

```json
{ "ok": true, "cleared": 3, "cursor": 3, "delivered": 3, "queued": 0, "dropped": 0, ... }
```

`cleared` 是**本次清掉的条数**；`dropped` 是**累计因队列满而丢弃的条数**。
两者语义不同，所以键名不同——早先版本里两者同名，展开时后者把前者覆盖了，是个真实 bug。

## GET /whoami

回显调用方身份，排查鉴权问题用。需要令牌。

```json
{ "ok": true, "plugin": "astrbot_plugin_dsh_bridge", "client_host": "1.2.3.4", "api_key_seen": true, ... }
```

## 状态与持久化

DSH 侧的状态文件默认在 `$DSH_HOME/integrations/dsh-astrbot/state.json`：

```json
{
  "version": 1,
  "cursor": 12,
  "bindings": {
    "aiocqhttp:FriendMessage:10001": { "sessionId": "sess-abc", "updatedAt": 1789200000000 }
  },
  "recentIds": ["evt-1789200000-11", "evt-1789200000-12"]
}
```

- `bindings` 是「聊天窗口 → Harness 会话」的映射，`/new` 会删掉对应条目。
- `recentIds` 只保留最近 200 个，用于游标重放时去重。
- 写入先写临时文件再 rename；`rename` 不可用的环境（受限 ACL、跨设备）退化为原地写。
- **存盘失败不影响收发**：`safeSave()` 只记日志。早先版本会把磁盘错误当成网络错误去打退避，
  导致取件停摆数秒，这是个真实 bug。
