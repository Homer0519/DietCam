## 仓库结构

| 路径 | 说明 |
| --- | --- |
| `astrbot_plugin_diet/` | AstrBot 插件：接收上传、落盘、调用模型、`/饮食` 指令、LLM 工具 |
| `android/` | Android 客户端（Kotlin + Jetpack Compose + CameraX） |
| `android/keystore/` | 签名密钥库放这里 —— **已被 .gitignore 排除，不进仓库** |
| `android/keystore.properties` | 签名配置（路径与口令）—— 只该留在本机，CI 从 Secret 还原 |
| `tools/` | 构建工具链、插件自测、JVM 自检、演示、版本号递增、打包 |
| `dist/` | 本地打包产物（`*.apk` / `*.zip` 都在 .gitignore 里） |
| `.github/workflows/build-apk.yml` | CI：编译 release APK、验签、上传产物 |

## 架构

```
┌──────────────┐   拍照    ┌───────────────────────────────┐
│  Android APP │ ────────► │  AstrBot 服务器 (公网)         │
│  CameraX     │  HTTP     │                               │
│  Compose     │  multipart│  astrbot_plugin_diet          │
└──────────────┘           │   ├─ 落盘 photos/<日期>/       │
        │                  │   ├─ 调用视觉模型分析          │
        │ 本地模式直连      │   ├─ 追加 records/<日期>.jsonl │
        ▼                  │   └─ /饮食 指令读取汇总        │
  你的 OpenAI 兼容 VLM ─────┤                               │
                           └───────────┬───────────────────┘
                                       ▼
                            你的多模态模型（本地或云端）
```

两条路共用同一套界面与数据模型，差别只在 `DietBackend` 的实现：
`DietApi`（HTTP 打插件）和 `LocalDietApi`（本机直接读写文件 + 直连模型）。
**改后端行为时两边都要动**，否则又会出现「本地有、服务器没有」那类只在一种模式下发作的毛病。

## 构建

### Android

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_android.ps1 -Task assembleRelease
```

- 产物：`dist/DietCam-<版本>-release.apk`
- 需要 JDK 17 及以上（本地用 21，CI 用 17，两边编出的包一致）
- 脚本自己找 Android SDK / Gradle；缺什么会明确报出来

> **Windows 上的一个坑**：PowerShell 5.1 把原生命令参数按 ANSI 传递，
> 一旦工作目录含中文（比如本机就是 `E:\DeepSeekHarness\astrbot插件相关\`），
> `java -cp ...` 的 classpath 会直接乱掉。脚本会在 `%TEMP%` 下建一个 **ASCII 目录联接**
> （`dietcam-build` / `dietcam-jvmcheck`）再在那里编译，绕开这件事。
> ⚠️ 目录联接**千万不能**用 `Remove-Item -Recurse` 删 —— 那会连目标内容一起删掉。

### 插件包

```powershell
python tools/package_plugin.py     # → dist/astrbot_plugin_diet-v<版本>.zip
```

## 测试与验证

一条命令跑完全部插件侧检查：

```powershell
python tools/run_all_checks.py
```

| 检查 | 说明 |
| --- | --- |
| `tools/plugin_selftest.py` | **329 项**单元 + 端到端测试 |
| `tools/verify_regression.py` | 验证测试本身有效（能把历史 bug 复现出来） |
| `tools/demo_plugin.py` | 端到端演示，兼作冒烟测试 |

本地模式（不连 AstrBot）的数据层在普通 JVM 上跑真实的 `LocalDietApi`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\jvmcheck\run.ps1
```

**104 项断言**，覆盖「存档案 → 重算目标 → 首页汇总 / 日历 / 历史 → 编辑删除 →
流式分片解析 → 运动记录与放纵日 → 更新检查与入参清洗」整条链。

它绕开 Gradle 的 `test` 任务：那个会 fork 测试 JVM 走本地 socket，在受限环境里会挂住；
这里直接调 kotlinc + java。另有 `TargetsMergeTest`
（`tools/build_android.ps1 -Task testReleaseUnitTest`）守着目标合并语义。

> ⚠️ **PowerShell 脚本必须带 UTF-8 BOM。** 这几支脚本里有中文，
> 而 `tools/` 下的 `.ps1` 是给 `powershell`（Windows PowerShell 5.1）跑的 ——
> 5.1 读无 BOM 的文件会按 GBK 解码，中文后面的引号会被当成双字节字符的一部分吞掉，
> 报出来是一堆莫名其妙的 `Unexpected token`。**加 BOM 的唯一原因就是这个**，
> 加的时候要按字节做（`[System.IO.File]::ReadAllBytes` + 前置 EF BB BF），
> 用 `Get-Content` 重写会把中文写坏。

### 关于桩的忠实性

插件测试跑在 `tools/astrbot_stub.py` 上 —— 一个**忠实模拟** AstrBot 的桩。
关键在于它复刻了 `PluginMultiDict` **不是 `dict` 子类**这一事实：
早期用普通 dict 冒充请求对象，导致一个真实 bug 被测试掩盖了整整一个版本（见下节）。

本地模式自检同样克制：`tools/jvmcheck/android-*-stubs.kt` 只给
`android.content / graphics / util` 补**最小**桩，多一个成员都不加，免得掩盖真机差异。

### 锚点断言

`tools/jvmcheck/LocalModeCheck.kt` 与 `tools/plugin_selftest.py` 里各有一组
**钉同一组数值**的断言（180cm / 80kg / 35 岁 / 中度 / 减脂 → **2176.2 千卡、蛋白 136 g、碳水 272 g**），
保证 Kotlin 与 Python 两份 `compute_targets` 不会各算各的。

### 日期不要跟着墙上时钟走

本地模式自检里曾经把 fixture 塞在写死的 `2026-09-17`，却让 `history(7, null)` 自己取「今天」——
日子一过，7 天窗口就滑过了那条记录，**测试自己会过期**（2026-10-07 实测两红）。
凡是「范围」类的断言都显式传 `end`；「不传 end 取今天」这条默认行为单独断言日期即可。

## 签名与版本（避免「安装」而不是「升级」）

Android 判断能否**覆盖升级**，看三件事同时满足：

1. `applicationId` 相同（`com.dietcam.app`）
2. 新包的签名与已安装版本**证书一致**
3. 新包的 `versionCode` **更大**

**① 签名固定，密钥不在仓库里。** 密钥库放 `android/keystore/dietcam-release.jks`（本机），
CI 从 GitHub Secret 还原；仓库里只有一份 `keystore.properties.example` 说明格式。
**签名密钥自始至终没换过**，所以装了任何历史版本的人都能一路覆盖升级。

```
CN=DietCam, OU=Personal, O=DietCam, C=CN
SHA-256: D7:6D:49:A7:C1:70:63:E6:69:CA:28:9E:7F:24:F5:EF:E7:D2:27:4A:DB:0E:AA:89:9A:FF:9B:A1:04:8B:5C:26
```

> 之前用 debug 签名是错的：debug 证书由每台机器 / 每次 CI 随机生成，指纹必然不同，
> 换台机器出的包只能卸载重装。密钥库有效期 10000 天（约 27 年），不会中途过期。

**② 版本号有工具管。** 发版前跑一次：

```powershell
python tools/bump_version.py 2.8.1     # versionCode 自动 +1，versionName 设为 2.8.1
python tools/bump_version.py --show    # 查看当前版本
```

只改 `versionName` 不顶用 —— 系统只认 `versionCode`。

**③ 极少数人要卸载一次。** 曾经短暂发过一版 2.7.0 用的是另一把实验密钥，
装了那一版的人需要卸载重装；除此之外所有版本都能一路覆盖升级。

⚠️ 密钥库和口令一旦更换，**所有用户都必须卸载重装**。别丢、别改。
密钥库另外单独备份在仓库之外的目录里。

### 仓库里为什么没有密钥

这个仓库是**公开**的，所以做过一次历史清理，把密钥库和明文口令从**所有**提交里抹掉了。

- **密钥库没换**，证书指纹因此保持不变，升级链没断；
- 因此 `git log` 里看不到任何 `.jks` / `keystore.properties`，只有 `keystore.properties.example`；
- `.gitignore` 继续挡住 `android/keystore/*.jks`、`android/keystore.properties`。

## 发布流程

1. `python tools/bump_version.py <新版本>`
2. 改 `astrbot_plugin_diet/metadata.yaml` 里的 `version`
3. `python tools/run_all_checks.py` + `tools/jvmcheck/run.ps1` 全绿
4. 构建 APK 与插件包到 `dist/`
5. 提交并推送，打 tag `v<新版本>`
6. 建 Release，上传**两个** APK：
   - `DietCam-<版本>-release.apk`（留档）
   - `DietCam.apk` —— **固定名，必须有**，否则下面的固定直链会 404
7. 上传 `dist/astrbot_plugin_diet-v<版本>.zip`

固定直链（README 里给用户的那条）：

```
https://github.com/Homer0519/DietCam/releases/latest/download/DietCam.apk
```

## CI

`.github/workflows/build-apk.yml`：push 到 `main` 且改动落在 `android/**` 或工作流自身时触发，
也可以手动 `workflow_dispatch`。步骤是「JDK 17 → 补 Android SDK → 从 Secret 还原签名 → assembleRelease → apksigner 验签 → 上传产物」。

**不要加回 `android-actions/setup-android@v3`**：它会把 runner 预装的 cmdline-tools
判成 `Wrong version in preinstalled sdkmanager`，然后去跑一个在新版 cmdline-tools 里
已被移除的 `sdkmanager tools`，整步直接失败（2026-09-19 起 ubuntu-latest 上必现，与本项目代码无关）。
工作流改为直接用镜像里已有的 SDK，只补 `platforms;android-35` 和 `build-tools;35.0.0`。

签名材料没配齐时，工作流会退化成 debug 签名并**显式告警** ——
debug 包无法覆盖升级正式包，不能当发布件用。

## 自动更新怎么实现的

App **一天最多一次**静默访问 `https://github.com/Homer0519/DietCam/releases/latest`，
从 302 跳转后的 URL 里解析版本号（`/tag/vX.Y.Z`）。

- **只有这一条路，不走 REST API。** 匿名 REST API 限 60 次/小时/IP，
  而网页跳转和 release 文件下载**不限流** —— 推广给一批人用时，这个差别是决定性的。
- 只有版本号确实更高才弹窗，然后交系统的 `DownloadManager` 下 APK 到「下载」目录，
  下完点通知栏那一项就能装。不申请「安装未知应用」权限，也不用 FileProvider。
- 检查失败**一律静默**，且**不写**「上次检查时间」——否则一次网络抖动会白白静默一整天。
- 「我的」页的「关于」卡片里有**检查更新**，手动点会明确给出结果，不做点了没反应的按钮。

> 这条链路依赖仓库是**公开**的：私有仓库的 release 要带 token，而 token 不能塞进 APK。

## 安全

- 上传接口除了 API Key，还要求 `X-Diet-Token: <exp>.<hmac_sha256(secret, exp)>`，5 分钟有效。
  两把钥匙分别放在 AstrBot 和 App 里，任一泄漏都不足以被滥用。
- 口令与密钥在写入设置时**去掉所有空白字符**：粘贴带来的换行曾让请求头里出现
  `Unexpected char 0x0a at 100 in Authorization value`（`trim()` 只去首尾，不够）。
- 路径穿越、超大文件、非法参数都有测试覆盖。
- 无论如何建议放在 HTTPS 反代之后，并考虑用防火墙限制来源 IP 段。

## 已修复的真实问题

### 2.6.2 / 插件 1.3.2 —— 本地模式没被当成一等公民

一份外部代码走查（只在本地留档，含明文口令，已进 .gitignore）逐行读完后，下面这些都被复现并修掉了。
共同点是：本地模式是后来加的，几处判断还停留在「必须有 baseUrl/secret」的旧假设上。

| 问题 | 根因 | 用户看到的现象 |
| --- | --- | --- |
| 本地模式下「档案 / 日历 / 回忆」三页永远空白 | 三个 `refresh*()` 用 `baseUrl`/`secret` 判空早退，而本地模式这两个字段本来就不填 | 给人用的那条路直接残废 |
| 本地模式下「保存并重算目标」点了没反应 | `saveProfile()` 的 `return` 排在 `_busy = true` 之前，静默返回 | 以为按钮坏了 |
| 回忆页选「90 天」实际只给 30 天 | `/history` 给只收 3 个参数的 `_pick()` 多传了 `type=int`，抛出的 `TypeError` 被紧邻的 `except` 吞掉 | 以为已经看全了 |
| 本地模式手动改目标会把其它三项清零 | `LocalDietApi.updateTargets` 整份替换 `targets`（插件版一直是先读再 merge） | 只填热量 → 蛋白/碳水/脂肪变 0 |
| 点「切换摄像头」画面黑掉 | `AndroidView` 的 `factory` 只跑一次，`DisposableEffect(lensFacing)` 只 `unbindAll()` 不重新绑定 | 切前后摄即黑屏 |
| 拍照失败、存相册失败全程无声 | 失败分支只 `file.delete()`，没有回传路径 | 不知道发生了什么 |
| 「关于」页版本号写死 `2.1.0` | 与真实构建脱节 | 报障时被这个数字带偏 |

同步补上的测试：`/history` 的 `days` 现在逐个断言「传 7 就回 7、传 90 就回 90」——
之前只断言 `days <= 365`，于是「参数整个失效」和一整套全绿测试可以同时成立，
**测试替实现圆了谎**。

### 2.1.0

* `too many values to unpack (expected 2)` —— 在 `astrbot_provider`（复用 AstrBot 提供商）模式下
  点拍照必现。根因是流式分支把 `_analyze()` 返回的 **dict** 当成元组解包。
* 相机页底栏跑到屏幕顶部并盖住返回按钮 —— `Crossfade` 的内容 lambda 不是 `BoxScope`，
  在里面写 `Modifier.align()` 不生效。改为在内容外包一层铺满的 `Box`。
* 主页「今天」被刘海遮挡 —— `LazyColumn` 缺少 `statusBarsPadding()`。

### 1.0.3

线上点拍照报 `缺少文件字段 file`。根因是 AstrBot 的 `PluginMultiDict` **不是 `dict` 子类**，
而插件里用了 `isinstance(files, dict)` 判断 —— 恒为 False，上传的文件和备注被静默丢弃，
「拍照+备注」的备注从未送达模型。修法是不再判断类型，改用鸭子类型取值（`_pick`）。

`tools/verify_regression.py` 会把这些 bug 的旧写法分别还原到副本上跑一遍，
确认测试确实能复现它们（复现结果：`400 缺少文件字段 file`、`too many values to unpack (expected 2)`）。
