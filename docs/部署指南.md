# DietCam 部署指南

从零到能用，大约 15 分钟。分两部分：**服务器端（AstrBot 插件）** 和 **手机端（Android APP）**。

---

## 0. 前置条件

| 项目 | 要求 |
| --- | --- |
| AstrBot | **v4.18.0 或更高**（需要插件 Web API），公网可访问 |
| 视觉模型 | 任意 **OpenAI 兼容** 的多模态接口（vLLM / Ollama / OneAPI / LM Studio / 通义 / 智谱 / OpenAI 都行） |
| 手机 | Android 8.0 (API 26) 及以上，能访问到 AstrBot 地址 |
| 构建 APK | 任选其一：GitHub 账号（用 Actions，推荐）或本地装 JDK 17 |

> 模型必须**能看图**。纯文本模型无法完成饮食识别。

---

## 1. 部署 AstrBot 插件

把仓库里的 `astrbot_plugin_diet/` 整个目录上传到 AstrBot 的插件目录：

```
AstrBot根目录/
└── data/
    └── plugins/
        └── astrbot_plugin_diet/
            ├── main.py
            ├── metadata.yaml
            ├── _conf_schema.json
            └── requirements.txt
```

然后在 WebUI →「插件」页面点**重载**（或重启 AstrBot）。看到日志里出现下面这行就成功了：

```
[diet] 已注册 5 个 Web API
[diet] 数据目录: /path/to/AstrBot/data/plugin_data/astrbot_plugin_diet
```

在聊天里发 `/饮食状态` 可以自检。

---

## 2. 配置插件

WebUI →「插件」→ 饮食管理 → 配置，逐项填写：

| 配置项 | 说明 |
| --- | --- |
| `llm_mode` | `openai_compatible`：插件直接请求你的模型（推荐）<br>`astrbot_provider`：复用 AstrBot 里已配置的提供商 |
| `base_url` | OpenAI 兼容地址，**填到 `/v1` 为止**，例如 `http://127.0.0.1:8000/v1` |
| `api_key` | 模型的 Key，本地模型可留空 |
| `model` | 模型名，例如 `qwen2.5-vl-7b-instruct` |
| `extra_headers` | 额外请求头（JSON），一般留 `{}` |
| `extra_body` | 额外请求体字段（JSON），例如 `{"top_p":0.9}` |
| `astrbot_provider_id` | 仅 `astrbot_provider` 模式需要；留空则用默认提供商 |
| `request_timeout` | 模型请求超时（秒），视觉模型建议 ≥120 |
| `hmac_secret` | **签名密钥**，自己编一个随机长串，手机端要填一样的 |
| `timezone_offset_hours` | 时区偏移，国内填 `8` |
| `analyze_prompt` | **拍照模式**的分析提示词，留空用内置营养师提示词 |
| `analyze_prompt_text` | **纯文字模式**的分析提示词，留空用内置文本营养师提示词 |

> **重要**：`hmac_secret` 请务必改成随机值，不要用默认的 `change-me-dietcam-secret`。
> 生成方法：`python -c "import secrets;print(secrets.token_hex(32))"`

### 用 Ollama 的例子

```json
{
  "llm_mode": "openai_compatible",
  "base_url": "http://127.0.0.1:11434/v1",
  "api_key": "",
  "model": "qwen2.5vl:7b"
}
```

---

## 3. 创建 API Key

WebUI →「设置」→「API Key」→ 新建：

- 权限**必须勾选 `plugin`**（插件 Web API 靠它鉴权）
- 复制生成出来的 `abk_...`，待会填到手机里

> 不需要 `chat` 或 `config` 权限，只给 `plugin` 最小权限即可。

## 4. 构建 APK

### 方式 A：GitHub Actions（推荐，不用装任何东西）

1. 把整个项目 push 到你的 GitHub 仓库
2. 仓库 →「Actions」→ 左侧选 **Build DietCam APK** →「Run workflow」
3. 等 3~5 分钟，在该次运行的页面底部 **Artifacts** 下载 `DietCam-release-apk`

工作流文件在 `.github/workflows/build-apk.yml`，push 到 `main` 且改动了 `android/` 时会自动触发。

### 方式 B：本地构建

需要 JDK 17+（JDK 21 也可以）。然后在项目根目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_android.ps1
```

> Windows 默认禁止执行 .ps1 脚本，所以必须带 `-ExecutionPolicy Bypass`。
> 装了 PowerShell 7 可以把 `powershell` 换成 `pwsh`。

首次运行会自动把 Android SDK 和 Gradle 下载到 `.toolchain/`（约 500MB），之后就是增量编译。
产物路径：`android/app/build/outputs/apk/release/app-release.apk`

两种方式产出的 APK **签名完全一致**，因为都使用仓库内固定的 `android/keystore/dietcam-release.jks`。
这一点很重要：只有签名一致，新包才能覆盖升级旧包，而不是被要求先卸载。

> 从旧版本升级时，先跑 `python tools/bump_version.py 1.0.1` 把 versionCode 加 1，
> 系统才会识别为升级。详见下面的「升级与版本管理」。

---

## 4.5 升级与版本管理

### 为什么有时会提示"安装"而不是"升级"

Android 只在三个条件同时满足时才允许覆盖升级：

| 条件 | 本项目的情况 |
| --- | --- |
| `applicationId` 一致 | `com.dietcam.app`，固定不变 |
| **签名证书一致** | 使用仓库内固定的 release 密钥库，证书 `CN=DietCam` |
| **`versionCode` 更大** | 用脚本递增，见下 |

只要改动其中任何一项，系统就会拒绝覆盖，表现为"应用未安装"或要求先卸载——
这就是"新包变成安装而不是升级"的原因。

> 早期版本曾用 debug 签名，而 debug 证书由每台构建机器随机生成，
> 指纹天然不同，所以本地和 CI 出的包无法互相覆盖。现已改为固定 release 密钥库。
> **如果你装过那个旧包，需要卸载一次**，之后就一路正常升级了。

### 发布新版本的流程

```bash
# 1) 递增版本号（versionCode 自动 +1，系统靠它判断升级）
python tools/bump_version.py 1.0.1

# 2) 构建
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_android.ps1

# 3) 或推到 GitHub 让 Actions 出包
```

产物示例：`dist/DietCam-1.0.1-release.apk`，直接覆盖安装即可。

> 只改 `versionName` 是不够的——系统只比较 `versionCode`。

### 查看当前签名

```bash
# Windows（用 SDK 里的 apksigner）
.toolchain\android-sdk\build-tools\35.0.0\apksigner.bat verify --print-certs app-release.apk
```

应当看到 `CN=DietCam, OU=Personal, O=DietCam, C=CN`。
若显示 `CN=Android Debug`，说明签名配置没生效，那个包无法覆盖升级。

### 密钥库相关

- 文件：`android/keystore/dietcam-release.jks`（已随仓库提交）
- 口令：`android/keystore.properties`
- 有效期：10000 天（约 27 年）

⚠️ **密钥库和口令不要更换、不要丢失。** 一旦更换，所有已安装的用户都必须卸载重装。

## 5. 安装并配置 APP

1. 把 APK 传到手机安装（需要允许「安装未知来源应用」）
2. 打开 APP，首次会自动弹出设置窗口，填写三项：

| 字段 | 填什么 |
| --- | --- |
| **AstrBot 地址** | `http://你的服务器IP:6185`（不要带结尾斜杠） |
| **OpenAPI Key** | 第 3 步拿到的 `abk_...` |
| **签名密钥** | 与插件里 `hmac_secret` **完全一致** |

3. 点「测试连接」，出现「连接成功 ✅ 插件版本 1.0.0」即通了
4. 保存，授权相机，开始拍照

## 6. 使用

APP 支持三种记录方式：

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 拍照 | 按快门 | 视觉模型识别菜品并估重 |
| **打字** | 输入框写吃了什么，按 ➤ | 不拍照也能记录，例如"中午吃了一碗牛肉面" |
| 拍照 + 打字 | 先打字再按快门 | 文字作为补充说明，估算更准，例如"这是一人份""少油" |

记录完 APP 会显示：

- 识别出的菜名、热量、蛋白/碳水/脂肪
- 逐项食物明细
- 一句营养建议

同时**自动归档**到服务器。**聊天里不会产生任何消息**。

> 打字记录没有照片，所以是纯文本推理，**模型不需要支持图片**——
> 普通文本模型也能用来记录。反过来，拍照模式必须是多模态模型。

想查看记录，在任意 AstrBot 会话里发指令：

| 指令 | 作用 |
| --- | --- |
| `/饮食` | 今天的日报 |
| `/饮食 昨天` | 昨天 |
| `/饮食 2026-06-27` | 指定日期 |
| `/饮食 本周` | 最近 7 天汇总（含日均摄入） |
| `/饮食 本月` | 当月汇总 |
| `/饮食状态` | 插件状态、数据目录、今日记录数 |

## 7. 数据在哪

默认在 `AstrBot/data/plugin_data/astrbot_plugin_diet/`：

```
astrbot_plugin_diet/
├── photos/2026-06-27/143210_a1b2c3d4.jpg   # 归档照片
├── records/2026-06-27.jsonl                # 当天记录，一行一条 JSON
└── state.json                              # 最近会话标识等
```

你之前提到希望以文件方式拿到结果——这正是设计目标：**记录就是文件**。
想看原始数据直接读 jsonl；想搬到别处，把整个目录软链过去即可。

## 8. 想先看看效果？

不用部署，直接在项目根目录跑演示脚本，它会用模拟的 AstrBot 环境走完整流程：

```bash
python tools/demo_plugin.py
```

输出包括：插件注册的 5 个接口、用合成炒饭照片跑出的分析结果、
`/饮食` 与 `/饮食 本周` 的真实回复、拒绝伪造签名的校验结果、
以及数据在服务器上的落盘结构。全程不需要模型服务。

## 9. 常见问题

**Q: 测试连接报 404 / JSON 解析失败**
插件没加载成功。确认 AstrBot ≥ 4.18，检查启动日志有没有 `[diet] 已注册 5 个 Web API`。

**Q: 报 401 / 未授权**
`hmac_secret` 和 APP 里填的签名密钥不一致，或者 API Key 没勾 `plugin` 权限。

**Q: 拍照后提示模型调用失败**
先用 curl 直接打一下模型接口确认能通；检查 `base_url` 是否填到了 `/v1`、`model` 名字是否正确、模型是否支持图片。

**Q: 分析结果不准**
视觉模型对中餐估重普遍偏乐观。可以在 `analyze_prompt` 里补充你的习惯（比如「我常吃外卖，份量按标准盒饭估」），或在 APP 里拍照时带上参照物（筷子、手）。

**Q: 手机连不上服务器**
确认手机和服务器网络可达、端口（默认 6185）已放行。

**Q: 装新版本提示"应用未安装"或要我卸载**
签名不一致，或 versionCode 没涨。用 `apksigner verify --print-certs` 确认证书是 `CN=DietCam`；
确认发布前跑过 `python tools/bump_version.py`。若你装的是早期的 debug 签名版本，卸载一次即可，
之后就能正常覆盖升级。

## 10. 安全建议

- 上传接口需要**两把钥匙**：API Key（`plugin` scope）+ `X-Diet-Token`（HMAC 签名，5 分钟过期）。任一泄漏都不足以被滥用。
- 仍然强烈建议放到 **HTTPS 反代**后面，避免明文传输。
- 可以把服务端口用防火墙限制到你自己的 IP 段。
- 定期备份 `astrbot_plugin_diet/` 目录，饮食记录是长期数据。
